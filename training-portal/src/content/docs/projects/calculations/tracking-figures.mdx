Once a baseline is approved, the **Budget tracking** table on the project's **Delivery** tab (and the window behind the **Budget left** button) compares the approved budget with what has been ordered and spent. All figures are in KES, before VAT.

## The rows

Each row is a **budget line**: one Odoo budgetary position, the same as in Odoo Budgets. Categories that share a position share a row, because the ledger can't tell them apart. With the standard set-up the rows are **Direct project costs** (equipment, software, subcontractors, installation materials, logistics), **Project travel and site**, **Project bonds and insurance** and **Project contingency**. A row called **Not split yet** collects categories with no position and any cost posted to an expense account that is in no position. Rows with nothing in them are hidden.

## The figures on each row

- **Planned**: the approved baseline's budget by category, added up for the row.
- **Expected by now**: the spend plan for every month up to and including the current month. See [spend by month](/projects/calculations/budget-lines-and-phasing/).
- **Committed**: confirmed purchase order lines carrying the project's cost account and not yet fully billed. For each line: (ordered quantity − billed quantity) × unit price, before VAT, × the project's share of the line, converted to KES at today's rate. Orders that are not yet confirmed, and cancelled orders, don't count. The row comes from the product: a product in a category linked to a cost type uses that type; otherwise services go to subcontractors and goods to equipment.
- **Spent**: everything posted to the project's cost account on expense accounts: bills, credit notes, journal entries and expenses. Payments, bank and VAT lines are left out. The row follows the account's budgetary position.
- **Left** = Planned − Committed − Spent. It is red when below zero.
- **Forecast at completion** = the larger of Planned and Committed + Spent. The whole-budget forecast adds the rows up, so savings on one line don't cancel an overrun on another.

## Status

Each row gets a status from Committed + Spent (the "used" amount):

| Status | When |
|---|---|
| **Over plan** | Used is more than Planned by over 0.50 |
| **Fully committed** | Planned is above 0 and used is at least 99.5% of Planned |
| **On track** | Anything else |

The project's **Budget status** is **Over plan** if any row is over plan, **Fully committed** only if every row is, and **On track** otherwise. Without an approved baseline it is **No approved budget**.

The **Spent so far** button shows Spent and, underneath, *Spent 66%*: Spent ÷ Planned × 100, rounded to a whole number.

## The warning on a purchase order

On a purchase order that carries a delivery project's cost account, the system checks each budget line the order touches:

- room = Planned − Committed on other orders − Spent, for that line;
- if this order's amount not yet billed is more than the room (by over 0.50), the order shows **Over the delivery plan.** with a line per project and budget line.

<Illustration name="projects/calc-po-over-plan" caption="The order is 20,000 more than what is left on the Direct project costs line." />

The warning never blocks. When the order is confirmed, the order's chatter records *Over the delivery plan when confirmed* and the project manager gets *Order over the delivery plan: P00045* on the baseline. If the room is already used up, the message says *nothing was left in the plan*.

## When the figures update

The **Budget status** and the smart-button figures are stored. They are refreshed every night, when someone clicks **Refresh**, after tender orders are tagged, when a baseline is approved and when the project closes. The **Figures as of** time shows the last refresh. The table on the **Delivery** tab is worked out each time you open the project.

## Edge cases

- **Order lines without the cost account** count as neither committed nor spent. On a tender with one delivery project, new purchase order lines get its cost account automatically. With two or more, the order says *This tender has 2 delivery projects: choose the cost account on each line.*
- **Lines shared between projects** count only the project's share, for example 40% of the line.
- **Foreign-currency orders** are converted at today's rate each time, so Committed can move without anyone changing the order.
- **Contingency** sits on a reserve account that nobody posts to, so its row only ever shows Planned and stays **On track**.

:::note[Good to know]
Because contingency never fills up, a project almost never shows **Fully committed** overall, and contingency adds to **Left**. Read the rows as well as the total.

A cost posted with the project's cost account on an expense account that is in no budgetary position lands in **Not split yet**. With the standard set-up nothing is planned on that row, so any such cost above 0.50 makes the project **Over plan**. Ask finance to check the account if you see this row.

The table you see on the **Delivery** tab is live, while the **Budget status** badge and the buttons show the last refresh. If they disagree, click **Refresh**.
:::
